# TestFlight и App Store — пошаговая инструкция для заказчика

Как подготовить приложение **Kindeks (SwiftUI App)** к тестированию через **TestFlight** и к публикации в **App Store**. Выполняется на **Mac** с **Xcode**; для магазина и внешнего TestFlight нужна **платная** подписка Apple Developer.

---

## 0. Что понадобится

- **Apple Developer Program** — [developer.apple.com/programs](https://developer.apple.com/programs/) (**99 USD/год**). Без неё нельзя опубликовать приложение в App Store и нельзя приглашать **внешних** тестеров в TestFlight (внутренние тестеры из команды — тоже только с активной программой).
- **Mac** с установленным **Xcode** (актуальная версия, с поддержкой вашей версии iOS в проекте).
- **Apple ID**, на который оформлена программа, добавлен в **Xcode → Settings (⌘,) → Accounts**.
- Исходный код проекта уже открывается и собирается локально (см. [CLIENT_SETUP.md](./CLIENT_SETUP.md)).

---

## Часть 1. App Store Connect — создание приложения

1. Откройте [appstoreconnect.apple.com](https://appstoreconnect.apple.com) и войдите под учётной записью с правами **Account Holder** или **Admin**.
2. Перейдите в **Apps** → кнопка **+** → **New App**.
3. Заполните:
   - **Platforms:** iOS  
   - **Name** — название в магазине (например, Kindeks)  
   - **Primary language**  
   - **Bundle ID** — **должен совпадать** с идентификатором в Xcode (**Signing & Capabilities** у таргета *SwiftUI App*). Сейчас в проекте указан идентификатор вида `toprete.com.SwiftUI-App`; при смене в Xcode тот же ID нужно зарегистрировать в Apple и выбрать здесь.
4. Если нужного **Bundle ID** нет в списке: [developer.apple.com](https://developer.apple.com) → **Account** → **Certificates, Identifiers & Profiles** → **Identifiers** → **+** → **App IDs** → зарегистрируйте App ID с **точно таким же** Bundle ID, как в Xcode.
5. **SKU** — любой внутренний уникальный код (например `kindeks-ios-1`), покупателям не показывается.
6. Сохраните приложение — в списке появится новая запись.

## Часть 2. Подготовка проекта в Xcode

### Версии

1. Откройте **`SwiftUI App.xcodeproj`**.
2. Выберите таргет **SwiftUI App** → вкладка **General**:
   - **Version** — версия для пользователей (например `1.0.0`).
   - **Build** — **целое число**, которое **увеличивается при каждой новой загрузке** в App Store Connect (`1`, `2`, `3`…). Повторно загрузить тот же Build нельзя.

### Иконка и материалы для магазина

- В **Assets.xcassets** заполните **AppIcon** по требованиям Apple (в т.ч. **1024×1024** без альфа-канала для публикации).
- В App Store Connect позже понадобятся **скриншоты** нужных размеров и тексты описания — их готовят отдельно (дизайнер/маркетинг).

### Конфиденциальность и разрешения (важно для модерации)

Любое использование камеры, микрофона, Bluetooth, геолокации, контактов и т.д. должно быть описано в **Info** (ключи вида **Privacy … Usage Description**). Если текста нет, Apple часто **отклоняет** сборку или билд падает при проверке.

- Для **Bluetooth** обычно нужен ключ **Privacy - Bluetooth Peripheral Usage Description** (и при необходимости другие — по фактическому коду приложения).

### Подпись

- **Signing & Capabilities** → включите **Automatically manage signing**.
- **Team** — команда с **активной** подпиской Developer Program.

## Часть 3. Сборка архива и загрузка в App Store Connect

1. В верхней панели Xcode выберите устройство **Any iOS Device (arm64)** или **Generic iOS Device** — **не** симулятор.
2. Меню **Product → Archive**.
3. После успешной сборки откроется окно **Organizer**. Выберите архив → **Distribute App**.
4. Выберите **App Store Connect** → **Upload** → пройдите шаги мастера (подпись обычно **Automatically**).
5. Дождитесь сообщения об успешной загрузке. На серверах Apple сборка обрабатывается **от ~10 минут до часа и более** — статус сначала **Processing**, затем становится доступной в TestFlight.

Если загрузка не удалась — читайте текст ошибки в Xcode и письма на почту аккаунта разработчика.

---

## Часть 4. TestFlight

1. В [App Store Connect](https://appstoreconnect.apple.com) откройте ваше приложение → вкладка **TestFlight**.
2. Когда сборка перестанет быть в статусе **Processing** и станет доступна для тестирования:
   - **Internal Testing** — до **100** пользователей с ролями в **Users and Access** / вашей команде App Store Connect. Приглашения приходят быстро; тестеры ставят приложение **TestFlight** из App Store.
   - **External Testing** — внешние тестеры по email или публичная ссылка. Обычно нужно заполнить **What to Test** и пройти **Beta App Review** при первой внешней группе (срок — от нескольких часов до пары дней).

Каждая **новая** сборка: увеличить **Build** в Xcode → снова **Archive → Upload** → в TestFlight выбрать новую сборку для группы тестеров.

---

## Часть 5. Публикация в App Store

1. В App Store Connect → ваше приложение → раздел **App Store** (не TestFlight).
2. Создайте **новую версию** (например `1.0.0`) и привяжите к ней загруженную **сборку** (**Build**).
3. Заполните обязательные поля магазина: описание, ключевые слова, категория, скриншоты, контакты, **URL политики конфиденциальности**, возрастной рейтинг (опрос), при необходимости — учётные данные для проверки (демо-логин).
4. Раздел **App Privacy** — анкета о сборе данных (даже если данных не собираете, это нужно явно указать).
5. Нажмите **Add for Review** / **Submit for Review**. После одобрения выберите способ выхода: **вручную** или **сразу после одобрения**.

Сроки проверки Apple — от нескольких часов до нескольких дней; при отказе приходит причина в Resolution Center.

## Краткая шпаргалка проблем

| Симптом | Что проверить |
|--------|----------------|
| Нет нужного Bundle ID в Connect | Создать App ID в developer.apple.com, совпадающий с Xcode. |
| Ошибка при загрузке | Версия **Build** уникальна; аккаунт с правами; сеть/VPN. |
| Сборка «зависла» в Processing | Подождать; проверить почту Apple; раздел **Activity** в Connect. |
| Отказ на ревью | Тексты Privacy, скриншоты, рабочая сборка, ответы в Resolution Center. |
